## Scope finding

The change is **prompt-only**. Verified by reading the code:

- `run.py:248` `handle_write_daily_note` — hash-verify then commit. No structural parsing.
- `run.py` passes `content` / `summary` / `script` straight through to GitHub, Slack, TTS.
- `_split_for_tts` (`run.py:303`) splits on sentence boundaries by length, not structure.

So no `run.py` edit is required. The entire restructure lands in `SYSTEM_PROMPT`
(`setup.py:24`).

## The deployment gotcha (most important item here)

`ensure_agent` (`setup.py:549`) hashes the agent config — model + system + tools. On any
`SYSTEM_PROMPT` change the hash drifts, and the code **archives the old agent and creates
a new one with a new `AGENT_ID`** (`setup.py:578`). It does *not* update in place.

Therefore:

> Editing `setup.py` and pushing changes **nothing**. The workflow keeps invoking the old
> archived-config agent via the existing `AGENT_ID` secret until `setup.py` is re-run and
> the secret is rotated.

`ENVIRONMENT_ID` is unaffected — `intended_env()` does not depend on the prompt.

## Rollback

`git revert` the commit, re-run `setup.py`, rotate `AGENT_ID` back. The old agent is
archived, not deleted, but re-running setup after a revert creates a *third* agent rather
than restoring the original — the ID will differ again. Rollback is therefore
"re-deploy the previous prompt", not "restore the previous agent".

## Out of scope

- Source health monitoring — explicitly declined
- Digest failure alerting — explicitly declined
- Adding ruff/pyright config, or a repo `CLAUDE.md` (this repo has neither; worth doing,
  but not in this change)
