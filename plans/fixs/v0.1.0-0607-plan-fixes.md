## Round 1

### Reviewer findings (openai / gpt-5.5)
1. **[HIGH]** [soft-requirement contract violation] (Task 5 Step 1, `main()` required env vars)
   The plan makes `OPENAI_API_KEY`, `SLACK_BOT_TOKEN`, `SLACK_CHANNEL_ID` hard startup
   requirements. If any audio-only secret is missing/misnamed/withheld, `main()` fails
   before the agent runs, so the note commit and text Slack post never happen — a full
   digest outage caused by an optional audio config problem, contradicting the stated
   soft-audio design.
   *Concrete fix:* keep only the hard-delivery env vars in `required`; read audio vars with
   `os.environ.get`, pass through, and have the handler return a soft `is_error` like
   `audio disabled: missing ...`. Log missing names after the loop without exiting nonzero.
2. **[MEDIUM]** [schedule/platform assumption] (Task 5 Step 6 `timezone:` key + `cron: '43 4 * * *'`)
   Relies on GitHub honoring `timezone:`. If unsupported, cron runs in UTC and fires at the
   wrong time / captures the wrong 24h window. No verification step confirms the parser
   accepted `timezone:` or that the next fire is ET-based.
   *Concrete fix:* don't depend on an unverified extension — encode UTC explicitly or use an
   external dispatcher; add a deploy verification of the next scheduled fire time.
3. **[MEDIUM]** [audio integrity risk] (Design decision 3 / Task 3 `synthesize_tts` byte-join)
   A 3–8 min script can exceed one chunk; raw MP3 byte concatenation can produce repeated
   headers, duration misreporting, seek problems, or playback that stops after segment 1 in
   some players. With soft-fail + only a manual play check, this can be a recurring
   user-visible failure.
   *Concrete fix:* constrain to a single ≤4000-char chunk, OR use `ffmpeg`/`ffprobe` on
   `ubuntu-latest` to concatenate/remux and validate duration before upload; add a dry-run
   check that multi-chunk output has expected duration and is playable.
4. **[MEDIUM]** [verification gap] (Tasks 3–6 test/deploy steps)
   Only the chunker is tested; imports just prove symbols exist. No coverage of the
   `send_audio_broadcast` event-loop branch, missing-secret behavior, OpenAI HTTP errors,
   Slack `ok:false`, upload-URL failure, or a successful 3-step upload (mocked).
   *Concrete fix:* add stdlib `unittest` tests with mocked `urllib.request.urlopen` for the
   success path and each soft-failure mode; keep them dependency-free.

2. **Accept (partial)** — Reject the "rewrite to UTC / `timezone:` unsupported" half: we

   IANA `timezone:` key is honored (DST-aware) and the repo's run date is after the ship

   to ~4:43 am ET and to NOT remove the key on a linter false-positive.
3. **Accept** — Upgraded Task 3 `synthesize_tts` to concatenate via `ffmpeg -f concat -c
   copy` (preinstalled on `ubuntu-latest`) for ≥2 chunks, with a raw byte-join fallback when
   ffmpeg is absent; single-chunk (common) ships unchanged. Refines the earlier owner-approved
   "naive byte-concat" decision in light of the sharper truncation risk (flagged to owner).
4. **Accept (scoped)** — Added `tests/test_audio_softfail.py` (stdlib `unittest`, mocked

## Round 2 (full re-review of the revised plan; diff machinery skipped — plan untracked so git baseline was empty)

### Reviewer findings (openai / gpt-5.5)
1. **[HIGH]** [platform/scheduling risk] (`daily-digest.yml` Task 5 Step 6 + Task 6 Step 6)
   Relies on a `timezone:` key under `on.schedule` and tells implementers to ignore linters
   that flag it. If GitHub doesn't accept the key, the workflow is invalid or cron runs as
   UTC (`43 4 * * *` ≈ midnight ET), defeating morning delivery.
   *Concrete fix:* validate against GitHub's actual parser; prefer UTC cron (with DST entries)
   or external workflow_dispatch; add a pre-deploy validation showing the next run in ET; do
   not instruct implementers to ignore schema/linter failures.
2. **[MEDIUM]** [silent feature failure / weak contract] (Task 5 Step 5; failure-modes)
   The new feature can disappear indefinitely while the job stays green — agent skips
   `send_audio_broadcast`, wrong/old `AGENT_ID` deployed, or prompt regresses; only a log
   warning. CI success becomes indistinguishable from successful audio delivery.
   *Concrete fix:* separate dependency soft-fail from orchestration-contract failure; require
   the agent at least attempted the tool (else fail or post explicit Slack warning); assert
   the active `AGENT_ID` exposes the new tool before running.
3. **[MEDIUM]** [audio integrity / environment assumption] (Task 3 `_concat_mp3`; decision 3)
   Multi-chunk audio depends on `ffmpeg` preinstalled on `ubuntu-latest`, but the workflow
   neither installs nor verifies it. If the image changes or a non-Ubuntu env is used, it
   falls back to byte-join (known-risky) while staying green.
   *Concrete fix:* make `ffmpeg` an explicit workflow dependency (apt install + verify), or
   treat missing/failed ffmpeg for multi-chunk as a soft failure rather than upload a
   known-risk byte-joined MP3.

## Implementation review (post-execution code review — separate from the plan review)

After implementing the plan via a workflow (2 impl agents + 3 reviewers: conformance,
correctness, integration), the code review surfaced these. All implementation checks were

**Fixed:**
- **[HIGH] Soft-fail contract was breakable.** `handle_send_audio_broadcast → synthesize_tts
  → _concat_mp3` had no exception guard; `_concat_mp3`'s file I/O + ffmpeg subprocess could
  raise and crash the run nonzero (defeating the whole soft-audio design). Fix: wrapped the
  synth+upload body of `handle_send_audio_broadcast` in try/except → soft error; wrapped
  `_concat_mp3`'s ffmpeg block in try/except → byte-join fallback. Added two tests
  (`test_unexpected_exception_is_soft`, `test_concat_byte_join_fallback_when_no_ffmpeg`).
- **[LOW] Stale `run.py` module docstring** — now lists the 3rd tool + the optional audio env vars.
- **[LOW] ffmpeg workflow step could fail the job** on a transient apt error despite the
  byte-join fallback — made it non-fatal (`|| echo ...`).
- **[LOW] cron comment** delivery-window wording tightened to match the real ~5:30–8:45am ET landing.
- **[hygiene] Tracked `__pycache__/*.pyc`** — added `.gitignore`; untracked the artifacts.

**Deferred (with rationale):**
- **[HIGH] requires_action backfill can hang** (`_handle_idle` / `backfill_custom_tool_uses`
  record tool-use ids without answering them). **PRE-EXISTING** code not touched by this
  change and in production; a correct fix needs the live SDK event model + testing. Flagged
  for a dedicated follow-up rather than a blind edit here.
- **[MEDIUM] `send_custom_tool_result` raises SystemExit on a failed result POST for the audio
  branch** — accepted: the trigger is session-comms failure (not audio), which is legitimately
  fatal; a hung audio tool-use would time out regardless.
- **[LOW] `_split_for_tts` drops leading/standalone `.!?` runs** — fidelity-only, size invariant
  holds, and the prompt tells the agent to avoid ellipses. Chunker tests assert current behavior.
- **[LOW] dead params** (`before_sha`, `run_start_utc`), **incomplete hex validation**,
  **no `_drive_session` audio-miss integration test** — pre-existing / low value; deferred.
