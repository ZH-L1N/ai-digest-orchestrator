# v0.2.0 — Digest content restructure

Status: accepted
Date: 2026-08-02
Supersedes the content sections of `plans/v0.1.0-0607-plan.md`

## Why

Two gaps in the v0.1.0 digest, plus one piece of evidence that changed the design.

**Gap 1 — missing categories.** The digest covers company announcements and industry
news. It has no coverage of *shippable products you can use today* (Product Hunt-class
launches, tool updates) and no *practitioner voice* at all. Every bullet is a corporate
announcement.

**Gap 2 — fragmentation.** Measured over 2026-07-10 → 07-15: 5–8 sections carrying
6–12 bullets, i.e. **~1 bullet per section**. Section headers consume as much vertical
space as content. The audio brief inherits the problem — "Anthropic. … OpenAI. … Google
AI. …", one sentence each, reads as a choppy list rather than a brief.

**The evidence that shaped the design.** A reference spec (a Chinese "AI 早报" bot)
proposed a pinned-RSS architecture with fixed per-source quotas. Probing all 31 candidate
sources on 2026-08-02 found **12 dead**, including *every* source backing its
applications section and *all five* of its tweet sources. This is the central finding:
**pinned source lists rot silently**, and a 200 response is not proof of life —
VentureBeat's AI feed returns HTTP 200 with 7 items whose newest entry is 2026-05-19,
stale by two and a half months.

That argues for keeping agent-driven discovery, which has no rot problem, and using a
verified source list only as a floor.

## Design

### Three-block structure

Replace the flat list of 12 entity sections with three top-level blocks. Block 1 keeps
the existing entity subsections unchanged.

```
AI Daily Digest — YYYY-MM-DD 🤖

━━━ 📰 Top Stories ━━━
  OpenAI            → • headline — why it matters — URL
  Google AI         → • …
  Hardware & Chips  → • …
  (existing entity/topic subsections, existing routing rules, unchanged)

━━━ 🚀 Ship & Use ━━━          (new)
  ⚡ product/tool — what it does — URL

━━━ 🐦 Community Pulse ━━━      (new; absorbs the old Trending GitHub section)
  💬 discussion/repo — one line — URL
```

### Block routing

**Block 1 vs Block 2 — the reader-action test.** Not company size, not topic.

> After reading this item, what does the reader *do*?
> "Noted." → Block 1.  "I'll go try that." → Block 2.

Worked examples:

| Item | Block | Why |
| --- | --- | --- |
| Cursor acquired by SpaceX | 1 (Industry/Deals) | Nothing to try |
| Cursor ships "Sand" agent | 2 | Go use it |
| GPT-5.7 released, benchmarks up | 1 (OpenAI) | Nothing to try |
| GPT-5.7 API open, priced at $X | 2 | Go integrate it |

A single company may appear in both blocks on the same day when it did two distinct
things. **One event appears exactly once** — when an item satisfies both tests, the
reader-action question decides, and it is not repeated.

**Block 3 — Community Pulse.** What practitioners are discussing: high-score Hacker News
AI threads, GitHub trending AI/agent repos, notable practitioner blog posts, and
(best-effort) Reddit. The old `Trending GitHub` section folds in here.

### Source-quality rule scope change

The v0.1.0 rule "prefer the OFFICIAL / primary source … drop unconfirmed rumor" applies
to **Blocks 1 and 2 only**.

Block 3 is exempt. Its subject *is the discussion*, so the thread, repo, or post is the
primary source. A high-score HN debate has no upstream "official" URL, and requiring one
would leave Block 3 permanently empty. Link directly to the discussion.

Product Hunt entries are unaffected — a maker's own submission is a primary source.

### Density — layered, not uniform

| Block | Items/day | Words/item | Rationale |
| --- | --- | --- | --- |
| 1 Top Stories | 6–12 (float) | ~55 | The who/what/why depth is the digest's actual value |
| 2 Ship & Use | 4–6 | ~25 | Scan-and-bookmark; depth is wasted |
| 3 Community Pulse | 3–4 | ~20 | Pointer-shaped by nature |

Total ≈ 15–22 items, ≈ 730 words.

**No hard floor on Block 1.** Today's 6–12 range is not a cap being hit — it is the agent
judging that only that many items clear the bar (`bias to FEWER, higher-signal`). A fixed
"12 items" target, as the reference spec uses, would force padding. Quality over quota is
retained verbatim. Blocks 2 and 3 are omitted entirely on days with nothing worth listing.

### Audio scope

Blocks 1 and 2 are read in full. **Block 3 is compressed to a single closing sentence**,
e.g. *"On the community side, folks are talking about X and Y — links are in the written
digest."*

Reading Block 3 aloud is a scenario mismatch: repo names, star counts, and thread titles
are unmemorable by ear and cannot be clicked while commuting. Estimated runtime ≈ 4.5 min,
inside the existing 3–8 min target.

### Language

All product output stays **English** — the Obsidian note, the Slack message, and the TTS
script. Marin is an English-first voice; this also removes any accent risk.

### HN keyword filter

The reference spec's naive substring match on `ai` is wrong: `campaign`, `email`,
`training`, `available`, `maintain`, `chair` all match. Probing confirmed a false
positive — *"'Crush this lady': how eBay harassment campaign led to $56M payout"* scored
as AI news. **Use word-boundary matching.** Keep the `score > 50` threshold.

## Non-goals and accepted risks

**Not building a fetch pipeline.** No RSS parsing code, no per-source quotas, no scheduled
fetch jobs. The anchor list lives in the agent's prompt as guidance. Discovery stays
agent-driven — that is what makes it rot-tolerant.

**Accepted: the anchor list will rot silently, unmonitored.** Explicitly decided against a
periodic health check. 12 of 31 candidate sources were already dead when this list was
built; expect similar decay within a year. There is no alarm — degradation shows up only
as quietly worse content. Revisit by re-running the probe manually.

**Accepted: digest failures remain unalerted.** Carried over from the GIT_PAT incident
(2026-07-16 → 08-02, 18 silent failures). A Slack failure notification was considered and
declined.

**Not changing** `run.py`, the three-tool contract, TTS voice/config, the 4:43am ET
schedule, or the commit path.
