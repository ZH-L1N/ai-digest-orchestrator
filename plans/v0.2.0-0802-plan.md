# v0.2.0 — Implement the digest content restructure

Date: 2026-08-02
Spec: `docs/superpowers/specs/v0.2.0-digest-content-spec.md` (what/why — read first)

## Scope finding

The change is **prompt-only**. Verified by reading the code:

- `run.py:248` `handle_write_daily_note` — hash-verify then commit. No structural parsing.
- `run.py` passes `content` / `summary` / `script` straight through to GitHub, Slack, TTS.
- `_split_for_tts` (`run.py:303`) splits on sentence boundaries by length, not structure.

So no `run.py` edit is required. The entire restructure lands in `SYSTEM_PROMPT`
(`setup.py:24`).

## The deployment gotcha (most important item here)

`ensure_agent` (`setup.py:549`) hashes the agent config — model + system + tools. On any
`SYSTEM_PROMPT` change the hash drifts, and the code **archives the old agent and creates
a new one with a new `AGENT_ID`** (`setup.py:578`). It does *not* update in place.

Therefore:

> Editing `setup.py` and pushing changes **nothing**. The workflow keeps invoking the old
> archived-config agent via the existing `AGENT_ID` secret until `setup.py` is re-run and
> the secret is rotated.

`ENVIRONMENT_ID` is unaffected — `intended_env()` does not depend on the prompt.

## Steps

### S1 — Rewrite `SYSTEM_PROMPT` (`setup.py:24`)

Edit these blocks; leave the rest of the prompt intact.

1. **Outputs preamble** — still three outputs (note, Slack, audio), unchanged contract.
2. **`## Sources to check`** — replace the prose category list with the 24-entry anchor
   table from the spec. Mark the all-topic feeds (†) as needing self-filtering and
   Anthropic/Meta (‡) as `web_fetch`-only.

   Phrase the list as **prioritized guidance, not a hard requirement**: *"these are the
   highest-value places to look; start here, go beyond them freely, and never pad to hit
   a per-source count."* Do **not** write "you must check all 24" — nothing in this
   design can verify it (see S6), and an unverifiable mandate in a prompt is just noise

3. **`## Source-quality rules`** — scope the official-source rule to Blocks 1–2; add the

4. **`## Categorization rules`** — prepend the three-block frame above the existing entity

5. **`## Dedup and length rules`** — replace the flat "max 4 bullets per section" with the

6. **`## Daily note format`** — add the three `━━━` block headers; keep entity subsections

### S2 — Add a prompt-guard test

New `tests/test_system_prompt.py`. The prompt is a long string with no other coverage; a
truncating edit would ship silently and only surface as a bad digest the next morning.

Structural assertions alone are too weak — a prompt can keep every header and URL while
losing the behavioral rules that actually shape the digest. Assert on
`setup.SYSTEM_PROMPT`, grouped:

*Structure*
- all three block headers present (`Top Stories`, `Ship & Use`, `Community Pulse`)
- every anchor URL from the spec's keep-list appears
- no removed URL appears — specifically `nitter`, `rsshub`, `xcancel`, `bensbites`,
  `therundown`, `aibusiness`, `cat=533`, `theverge.com/ai-artificial-intelligence`
- length sanity: `len(SYSTEM_PROMPT) > 6000`

*Behavioral contracts* — each needs a representative exact phrase, so deleting the rule
fails the test rather than merely shortening the prompt:
- the three density ranges `6-12`, `4-6`, `3-4`
- `bias to FEWER` (no-padding rule)
- `one event appears exactly once` (cross-block dedup)
- the reader-action test ("what does the reader do")
- the Block 3 official-source exemption
- Block 3 compressed to one closing sentence in the broadcast format
- HN word-boundary matching **and** `score > 50`
- Reddit 429 skip-silently behavior
- English-only output

Choose phrases that are load-bearing prose, not incidental words, so the test fails on
rule removal and not on harmless rewording.

Import `setup` without network: it only imports `anthropic` at module scope and
constructs no client until `main()`, so a plain `import setup` is safe.

### S5 — Deploy (blocked on user — needs `ANTHROPIC_API_KEY` locally)

Rotation must be fail-closed. A bare `gh secret set AGENT_ID --repo ...` reads the value
interactively and will happily accept an empty or mistyped paste; because the old agent is
archived by this point, a wrong value leaves no working agent at all.

**Run this in `bash`, not `fish`.** The repo owner's default shell is fish, where `$?`
and `set -o pipefail` are syntax errors. Start a `bash` subshell first.

Note the log is written with `>` rather than piped to `tee`: in a pipeline the shell
reports `tee`'s exit status, not Python's, so a `setup.py` that printed an ID and *then*
failed would still pass the check and get its half-finished ID promoted into the secret.

```bash
set -euo pipefail
export ANTHROPIC_API_KEY=sk-ant-...

if python setup.py > /tmp/setup-v0.2.0.log 2>&1; then
  SETUP_RC=0
else
  SETUP_RC=$?
fi
cat /tmp/setup-v0.2.0.log
test "$SETUP_RC" -eq 0 || { echo "FATAL: setup.py exited $SETUP_RC — not rotating"; exit "$SETUP_RC"; }

NEW_AGENT_ID=$(grep -oE 'AGENT_ID=[A-Za-z0-9_-]+' /tmp/setup-v0.2.0.log | tail -1 | cut -d= -f2)
test -n "$NEW_AGENT_ID" || { echo "FATAL: no AGENT_ID parsed"; exit 1; }

gh secret set AGENT_ID --repo ZH-L1N/ai-digest-orchestrator --body "$NEW_AGENT_ID"
```

The `if` wrapper is load-bearing. Under `set -e` a bare `python setup.py; SETUP_RC=$?`
aborts the script the moment Python exits non-zero — the capture, the `cat`, and the
FATAL message never run, so the operator gets no diagnostic and no log dump. Only `if`,
`||`, `&&`, and `!` contexts suppress errexit.

#### If `SETUP_RC != 0` — check the log before doing anything

`ensure_agent` archives the old agent *before* creating the new one
(`setup.py:573` then `:578`, neither guarded by the other's success). Whether a failure
matters depends entirely on **which side of the archive** it happened on. Grep the log
first — the wrong branch here causes the outage rather than fixing it.

```bash
grep -E 'archiving|recreating|created agent:' /tmp/setup-v0.2.0.log
```

**Branch A — no `archiving`/`recreating` line. Safe no-op.**
Setup died before touching the old agent: bad `ANTHROPIC_API_KEY`, missing dependency,
network failure, any preflight error. The old agent is live and `AGENT_ID` still points
at it, so the schedule keeps producing v0.1.0-format digests exactly as before.
**Do not rotate. Do not disable the workflow.** Fix the local problem and retry whenever
convenient — there is no time pressure and no outage.

**Branch B — `archiving`/`recreating` present but no `created agent:`. Service is down.**
The old agent is archived and `AGENT_ID` points at it, so the next 4:43am run goes red,
unalerted. Recover now:

1. **Re-run the block.** This is the fix in almost all cases: with the old agent archived,
   `find_matching` returns nothing, so `ensure_agent` goes straight to create and prints a
   fresh `AGENT_ID`. Rotate as normal.
2. Only if setup keeps failing and you cannot finish before the next schedule, park the
   workflow rather than let it log an unobserved failure:
   `gh workflow disable daily-digest.yml --repo ZH-L1N/ai-digest-orchestrator`, then
   `gh workflow enable` once the rotation completes.

Making `ensure_agent` create-then-archive would remove Branch B entirely, but that
rewrites the deploy path to guard a low-probability failure that one re-run already
recovers from. Deliberately not done here — noted in Out of scope.

Then verify all three, in order:

1. The setup log contains `agent ... config drift ... - recreating`. If it reads
   `reusing agent`, the prompt edit did not register and the deploy is a **no-op**.
2. `$NEW_AGENT_ID` matches the `created agent:` line in the same log.
3. `gh secret list --repo ZH-L1N/ai-digest-orchestrator` shows `AGENT_ID` updated to
   today's timestamp.

`setup.py` prints both IDs; only `AGENT_ID` needs rotating — `ENVIRONMENT_ID` is unchanged.

**Failure mode if this is botched:** an archived or invalid `AGENT_ID` makes
`sessions.create` raise, so `run.py` exits non-zero and the workflow goes red. It does
*not* silently serve stale content. But since failure alerting was declined, a red run is
only visible to someone who looks — so do not rotate late in the evening and leave it
unverified over the 4:43am ET run.

### S6 — Verify

Next scheduled run is 4:43am ET (lands ~5:30–6:45am after typical delay). Check:

1. `gh run list --repo ZH-L1N/ai-digest-orchestrator --limit 1` → success
2. The committed note has all three block headers and 15–22 items
3. Audio length ≈ 4.5 min, and Block 3 is one sentence, not a list
4. **Anchor-source coverage, measured from the notes themselves.** Source access is not
   observable: `run.py`'s event loop handles only `agent.message` (truncated to 200 chars)
   and `agent.custom_tool_use`, so server-side `web_search`/`web_fetch` calls never reach
   the workflow log. Inspecting the session event stream would require a `run.py` change,
   which is out of scope.

   Use the committed notes as the proxy instead — extract cited hostnames across the
   first ~7 days post-deploy and compare against the anchor list:

   ```
   grep -ohE 'https?://[^ )]+' 2026/08/*.md | awk -F/ '{print $3}' | sort | uniq -c | sort -rn
   ```

   Expect a spread across anchor domains. A week where Block 2 never cites Product Hunt,
   or Block 3 never cites `news.ycombinator.com` or `github.com`, means the floor is not
   holding and the prompt wording needs strengthening. This is a weak signal — citing a
   source proves it was read, but *not* citing one does not prove it was skipped — so
   treat it as a smell test, not a gate.

A manual `gh workflow run daily-digest.yml` also works but posts to Slack — the user has
previously asked not to trigger Slack messages for testing, so prefer waiting for the
scheduled run unless they say otherwise.

## Rollback

`git revert` the commit, re-run `setup.py`, rotate `AGENT_ID` back. The old agent is
archived, not deleted, but re-running setup after a revert creates a *third* agent rather
than restoring the original — the ID will differ again. Rollback is therefore
"re-deploy the previous prompt", not "restore the previous agent".

## Out of scope

- Any `run.py` change
- RSS-fetching code, per-source quotas, scheduled fetch jobs (see spec non-goals)
- Source health monitoring — explicitly declined
- Digest failure alerting — explicitly declined
- Adding ruff/pyright config, or a repo `CLAUDE.md` (this repo has neither; worth doing,
  but not in this change)
- Reordering `ensure_agent` to create-before-archive. It would close the mid-deploy
  window described in S5, but the recovery there is a single re-run, and rewriting the
  deploy path is a worse trade than documenting it. Revisit if it ever actually fires.
